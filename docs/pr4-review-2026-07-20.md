# PR #4 Review — v5 Identity & Membership (2026-07-20)

Two independent passes (code review vs spec + adversarial security audit). Both converge.

## Verdict: REQUEST CHANGES — merge after the 4 blockers below

The RPC layer, migrations, token hygiene, and harness are genuinely well built (details at bottom). The problems are at the *table-RLS* layer and in two client flows.

---

## Blockers (fix before merge)

### 1. [CRITICAL] Direct-table RLS bypasses the entire role hierarchy
`users_admin_update` / `users_admin_insert` (multi_tenancy.sql:206-212) allow any active admin to UPDATE/INSERT any `users` row in their mandal with **no column restrictions**. Two plain supabase-js calls escalate an admin to owner:
```js
await supabase.from('users').update({ role: 'volunteer' }).eq('id', OWNER_ID)  // vacates owner slot
await supabase.from('users').update({ role: 'owner' }).eq('id', MY_ID)         // takes it
```
Also possible: deactivate the owner, rebind `auth_user_id` to an attacker identity, and `insert` a brand-new admin membership bound to any auth uid — bypassing create_invite/accept_invite/set_member_role/transfer_ownership/sole-owner protection entirely. Owner-only `purge_donations` is then reachable.

**Fix (either):**
- Drop `users_admin_insert` and `users_admin_update` — every legitimate write path is already a SECURITY DEFINER RPC (same pattern as the zero-policy `invites` table); route any remaining name/phone edits through a narrow RPC; **or**
- Keep them but add a `forbid_privileged_user_edit` BEFORE UPDATE trigger (mirror of `forbid_financial_edit`) rejecting changes to `role, active, auth_user_id, mandal_id, email`, and tighten the insert check to `role='volunteer' and auth_user_id is null` (though removal is cleaner).
- Verify each membership RPC still works after the change (definer functions and trigger interaction).

### 2. [CRITICAL-UX] "Resend" destroys the invite and discards the replacement
`members.tsx:125-136` calls `resendInvite(invite.id)` and ignores the returned raw token — but resend revokes the old link and the new token is returned exactly once (only its hash is stored). Net effect: tapping Resend kills the person's only link and shows nothing to share. Fix: pipe the returned token into the same link-ready UI the invite sheet uses. Add the missing resend test (ManageMembers has none — which is where this hid).

### 3. [HIGH] Harness never tests the direct-table attack class
All membership assertions in verify-local.sh go through RPCs; all direct `users` writes in the script run as superuser (fixture setup), so the wide-open policies are invisible to the suite. Add adversarial `role authenticated` blocks: admin direct `update role='owner'` fails; admin direct `update active=false` on owner fails; admin direct `insert role='admin'` fails; plus a session-determinism assertion for a two-mandal identity (`app_mandal_id()` returns the most-recent membership — the ORDER BY exists but is untested).

### 4. [HIGH] Anon-upgrade banner likely fails at runtime + hangs on error
`AnonUpgradeBanner.tsx:24-27` calls `supabase.auth.linkIdentity(...)` but `config.toml:182` has `enable_manual_linking = false` (and no prod-dashboard checklist note). On any error, `busy` stays true forever and nothing is shown. Fix: enable manual linking (local + prod deploy checklist), handle the error, reset `busy`.

## Should-fix (same PR or immediate follow-up)

9. **Referrer/URL hygiene on /join/:token:** add `no-referrer` meta / referrerPolicy on the join route, strip the token from the URL after preview, and consider dropping `invitee_name` from `invite_preview` (PII to any link bearer); edge rate-limit preview/accept.

## Spec deviations — all deliberate and documented (accepted)
No dual-invite transition window (old `/invite/:token` links die honestly), create_mandal one-mandal guards removed, delete-mandal not built, anon sign-ins flipped off locally with written rationale. Residual: the prod dashboard steps (anon toggle, manual-linking flag) need a deploy checklist entry.

## What's strong (keep)
256-bit tokens, sha256-at-rest, raw token returned once, zero-policy invites table; SECURITY DEFINER hygiene + per-function grants; migration ordering with documented invariants; the `created_at desc, id desc` determinism fix applied to all three session helpers AND the client; the isAdminRole sweep incl. reconcile owner-tier with updated algebra tests; deactivated members provably locked out; harness coverage of RPC-level escalation, tenant scoping, token lifecycle, and sole-owner protection.
